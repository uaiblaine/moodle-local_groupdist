Multi-rule affinity — prototype

Four explorations: the rule builder (step 1, replacing the old "Affinity by profile field" section), the member enrolment options (with the new future-start option and the "sticky footer carries actions only" rule), three explainability alternatives in the preview (step 2) and the audit log with a snapshot of the data — this is where alternative B lives.

What shipped: the rule builder and the enrolment options as prototyped here; in the preview, alternative A (per-rule badges on the group card) together with alternative C (the collapsible "Rules report"), while alternative B ("why here?", per participant) became the audit log's own screen — now paged and searchable, prototyped in distribution-log.html. Section 3 below is the original exploration of that log and is kept as the design record.

Since then: the rule builder's type picker gains a third kind — an existing course group — prototyped separately in rule-source-groups.html, which also carries the decisions that come with it (the picker's bound, a destination group used as its own source, group visibility, and the wording a binary membership source needs). This file still shows the two original types only.

Prototype Everything is interactive: reorder the rules by dragging the ⠿ handle or with the ▲▼ buttons, change the field or strategy, add and remove rows. In the preview alternatives, tab B has clickable participants. It follows the visual system of the approved mockups (docs/mockups/).
